# Contributing to Persona 2: Eternal Punishment Native Port

Thank you for your interest in contributing to this project! This document outlines the rules and guidelines for contributing to this open-source project.

## 📋 Code of Conduct

Please note that this project is released with a [Contributor Code of Conduct](#code-of-conduct). By participating in this project you agree to abide by its terms.

## 🌟 How to Contribute

### Reporting Bugs

This section guides you through submitting a bug report for Persona 2: Eternal Punishment Native Port. Following these guidelines helps maintainers and the community understand your report 🐞.

Before creating bug reports, please check existing issues to see if the problem has already been reported.

#### How Do I Submit a Good Bug Report?

Bugs are tracked as GitHub issues. Create an issue and provide the following information:

- **Use a clear and descriptive title** – The title should be a short summary of the bug.
- **Describe the actual behavior** – Describe exactly what the bug does.
- **Describe the expected behavior** – Describe exactly what you expected to happen.
- **Provide version information** – Include the version of the port, the game, and the operating system.
- **Provide a reproducible example** – If you can, provide a minimal example that reproduces the bug.
- **Provide screenshots or logs** – If applicable, include screenshots or logs that demonstrate the bug.

#### How Do I Submit a Feature Request?

Feature requests are tracked as GitHub issues. Create an issue and provide the following information:

- **Use a clear and descriptive title** – The title should be a short summary of the feature.
- **Describe the problem** – Describe the problem you're trying to solve and why the feature is needed.
- **Describe the proposed solution** – Describe your proposed solution and why it's the best solution.
- **Provide examples** – If applicable, provide examples of how the feature would be used.

### Pull Requests

This project is open to pull requests. However, before submitting a pull request, please ensure that:

1. **You have read the [Code of Conduct](#code-of-conduct).**
2. **The pull request is relevant to the project.**
3. **The pull request follows the project's coding standards.**
4. **The pull request includes tests.**
5. **The pull request includes documentation updates.**
6. **The pull request includes a description of the changes.**

#### Pull Request Process

1. **Fork and clone the repository.**
2. **Create a new branch from `main`.**
   ```bash
   git checkout -b feature/your-feature-name
   ```
3. **Make your changes.**
4. **Add tests for your changes.**
5. **Run the test suite and ensure all tests pass.**
   ```bash
   make test
   ```
6. **Update documentation if necessary.**
7. **Commit your changes.**
   ```bash
   git commit -m "Add some feature"
   ```
8. **Push to your fork.**
   ```bash
   git push origin feature/your-feature-name
   ```
9. **Create a pull request.**

#### Pull Request Guidelines

- **One thing at a time** – Keep pull requests focused. If you have multiple changes, submit them as separate pull requests.
- **Write clear commit messages** – Follow the [Conventional Commits](https://www.conventionalcommits.org/) specification.
- **Update documentation** – If your changes affect the user-facing behavior, update the documentation.
- **Add tests** – All changes should be accompanied by tests.
- **Run the test suite** – Ensure all tests pass before submitting your pull request.

### Styleguides

#### Git Commit Messages

- Use the present tense ("Add feature" not "Added feature")
- Use the imperative mood ("Move cursor to..." not "Moves cursor to...")
- Limit the first line to 72 characters or less
- Reference issues and pull requests liberally after the first line
- When possible, use one of the [conventional commit types](https://www.conventionalcommits.org/en/v1.0.0/#summary)

#### Code Style

- **Indentation**: 4 spaces (no tabs)
- **Line length**: 100 characters max
- **Comments**: Use JSDoc-style comments for functions and classes
- **Naming**: Use descriptive names for variables and functions
- **File structure**: Organize files logically (e.g., group related code together)
